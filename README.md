# SMS Gateway для MikroTik и Entware

Веб-интерфейс и API для LTE-модема MikroTik (T2), работает на Netcraze под Entware:
`http://192.168.1.1:8099`. Только стандартная библиотека Python 3, без зависимостей.

- **Входящие.** Каждые 30 секунд читает исходные PDU через RouterOS API и `AT+CMGL`: UCS2/кириллица, GSM7,
  склейка частей длинных SMS. Архив — `archive.sqlite`, исходные PDU тоже сохраняются. После записи в архив
  сообщение удаляется с SIM; нераспознанные PDU остаются на SIM и перечитываются при каждом опросе.
  Модем кладёт на SIM и копии отправленных SMS (SMS-SUBMIT) и отчёты о доставке (SMS-STATUS-REPORT): они
  архивируются, освобождают ячейку и не показываются как входящие.
- **Интерфейс.** Диалоги по отправителю, группировка по дням или общим списком, сортировка, фильтр
  непрочитанных, поиск. Сообщение помечается прочитанным при открытии диалога; можно вернуть «непрочитано».
  Адаптивная вёрстка, светлая и тёмная темы.
- **Выделение и массовые действия.** «Выбрать» в списке (или Ctrl/⌘+клик, Shift+клик для диапазона, долгое
  нажатие на телефоне). В режиме «Диалоги» выделяются отправители целиком, в остальных — отдельные сообщения.
  Действия: прочитано, непрочитано, переслать (до 20 сообщений одной операцией), удалить из архива.
  Удаление необратимо и касается только входящих; отправленные остаются в журнале.
- **Контакты.** Имена вместо номеров во входящих, исходящих, журнале и при отправке. Импорт vCard (.vcf) с
  телефона и CSV (в том числе экспорт Google Контактов); номера совпадают по последним 10 цифрам. Просмотр,
  добавление, правка и удаление в разделе «Контакты». В пересылаемом SMS указывается имя отправителя.
- **Отправка.** Штатный `/tool/sms/send`, только GSM7 до 160 единиц: RouterOS 7.20.5 не отправляет
  кириллицу. Кнопка «В транслит» преобразует текст до отправки. Успех — подтверждение RouterOS, а не доставка.
- **Отчёты о доставке.** Каждое SMS отправляется с запросом отчёта. Отчёт сопоставляется с отправкой по
  номеру и времени приёма у оператора (окно ±15 минут) и показывается у сообщения и в журнале: доставлено,
  не доставлено, ждём отчёт. Без отчёта за 3 дня состояние — неизвестно.
- **Пересылка.** Новые входящие отправляются на заданный номер (Настройки → Пересылка SMS): текст
  транслитерируется, длинное сообщение делится на части с номерами `(1/3)`, число частей ограничено.
  Пересылаются только сообщения, пришедшие после включения; сообщения с самого номера пересылки не
  пересылаются; не больше 20 пересылок в час; неудачная отправка не повторяется автоматически — её можно
  повторить кнопкой «Переслать» у сообщения. Кнопка «Отправить тест» шлёт пробную пересылку.
- **USSD.** Баланс T2 `*105#`, номер `*201#`, произвольные запросы. Ожидание до 120 секунд; EG18 может
  прерывать LTE во время USSD. Автоматических USSD-запросов нет.
- **Лимит SMS.** Месячный лимит и день его обновления (1–28) задаются в Настройках. Считается каждое SMS,
  подтверждённое RouterOS: из интерфейса, API и каждая часть пересылки. При исчерпании отправка
  отклоняется (API — `429`), а новые сообщения помечаются «не переслано: лимит», чтобы после обновления
  не ушли пачкой. `0` — без лимита.
- **Журнал.** Все операции с результатами; одна операция модема за раз; idempotency id у каждой операции.

Прямой `AT+CMGS` через RouterOS at-chat не используется: при проверке он подвешивал модем.


## Установка одной командой

На Keenetic/Netcraze с Entware, в SSH роутера:

```sh
curl -fsSL https://raw.githubusercontent.com/x-happy-x/sms-gateway/master/install.sh | sh
```

Установщик ставит Python 3 из Entware, файлы шлюза в `/opt/sms-gateway` и
init-скрипт, спрашивает адрес RouterOS (MikroTik с LTE-модемом), пользователя и
пароль, адрес и порт веб-интерфейса, запускает шлюз и проверяет `/api/health`.
Пароль вводится на роутере и попадает только в `config.json` (права 600).
Повторный запуск обновляет шлюз: `config.json` и архив SMS остаются, прежние
файлы копируются в `/opt/sms-gateway/backup-<время>`. Параметры: `--version=`
(тег или ветка), `--dry-run`, `--uninstall`. Тот же шлюз ставится из общего
установщика HomeNet (компонент «SMS-шлюз»).

## API

Все запросы `/api/v1/*` требуют `Authorization: Bearer <token>`. В `config.json` хранится только SHA-256
токена. Выпуск токена на роутере (показывается один раз), затем перезапуск:

```sh
/opt/bin/python3 /opt/sms-gateway/server.py token add my-service
/opt/bin/python3 /opt/sms-gateway/server.py token list
/opt/bin/python3 /opt/sms-gateway/server.py token remove my-service
/opt/etc/init.d/S99sms-gateway restart
```

| Метод | Путь | Описание |
|---|---|---|
| GET | `/api/v1/messages` | Входящие. `unread=1\|0`, `sender`, `since` (Unix-время или ISO 8601), `order=asc`, `limit` (1–500), `offset` |
| GET | `/api/v1/messages/{id}` | Одно сообщение (любой id из `ids` составного SMS) |
| POST | `/api/v1/messages/read` | `{"ids": [1, 2], "read": true}` — отметить прочитанными или нет |
| POST | `/api/v1/send` | `{"number": "+7…", "text": "…", "id": "необязательный idempotency id"}` → `202 {"id", "status_url"}` |
| GET | `/api/v1/operations/{id}` | Статус отправки: `pending`, `done`, `error`, `unknown`; `delivery.state`: `delivered`, `failed`, `pending`, `unknown` |
| GET | `/api/v1/limits` | Месячный лимит: `monthly`, `reset_day`, `used`, `remaining`, `next_reset` |
| GET | `/api/v1/contacts` | Контакты: `id`, `name`, `number`, `note` |
| GET | `/api/health` | Без токена, для healthcheck |

```sh
curl -H "Authorization: Bearer $TOKEN" "http://192.168.1.1:8099/api/v1/messages?unread=1"
curl -X POST -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"number":"+79990000000","text":"Hello"}' http://192.168.1.1:8099/api/v1/send
```

В сообщениях API есть `sender_name` — имя из контактов или `null`. Повтор `send` с тем же `id` не отправляет SMS второй раз. Одновременно выполняется одна операция модема,
остальные получают `409`.

## Устройство

| Файл | Назначение |
|---|---|
| `server.py` | HTTP: интерфейс (CSRF-токен на изменяющих запросах), API, CLI токенов |
| `gateway.py` | Операции модема: архив, очистка SIM, USSD, отправка, пересылка |
| `store.py` | SQLite: сообщения и прочитанность, операции, настройки, пересылки, контакты |
| `contacts.py` | Разбор vCard и CSV, нормализация номеров |
| `pdu.py`, `routeros.py` | Кодеки SMS и клиент RouterOS API |
| `static/` | Интерфейс без сборки: HTML, CSS, JS |

На роутере рядом с кодом лежат `config.json` (права 600, логин RouterOS и хэши токенов) и
`archive.sqlite`; деплой их не трогает. На MikroTik используется пользователь `smsgw` (read, write, test,
api), вход разрешён только с 192.168.188.254; для USSD — memory logging action `smsgw` на 100 записей и
правило с prefix=smsgw и regex `CUSD:|CMGS:|CMS ERROR`.

## Разработка и деплой

```sh
make test   # unit-тесты без модема
make run    # локально с архивом из .local/dev (роутер в .local/dev/config.json должен быть недоступен)
```

Деплой из PowerShell (ключ `~/.ssh/keenetic_ed25519` из `dms.yml`, рядом нужен `P:\homenet\dms`):

```powershell
.\deploy.ps1
```

Скрипт прогоняет тесты, собирает `dms-client.exe` и `dms-service` под arm64 и выкладывает релиз. DMS
копирует файлы кода и `static/` в `/opt/sms-gateway`, ставит симлинк `/opt/etc/init.d/S99sms-gateway`,
перезапускает сервис и проверяет `/api/health`. Если проверка не прошла, прежние файлы возвращаются и
сервис перезапускается на них. Резервные копии заменённых файлов — в `/opt/dms/apps/sms-gateway/backups/`.

Ручной откат на роутере:

```sh
ls /opt/dms/apps/sms-gateway/backups/
# artifact-N — файлы в порядке artifacts из dms.yml
/opt/etc/init.d/S99sms-gateway restart
```

## Управление на Netcraze

```sh
/opt/etc/init.d/S99sms-gateway status|restart|stop
```

Лог: `/opt/var/log/sms-gateway.log`.

## Резервная копия

Для согласованной копии SQLite используйте `sqlite3` `Connection.backup()` или остановите сервис и копируйте
каталог целиком (включая `-wal`/`-shm`). `config.json` содержит секреты: права 600, не публикуйте.

Документация: [SMS](https://help.mikrotik.com/docs/spaces/ROS/pages/62390313/SMS),
[LTE](https://help.mikrotik.com/docs/spaces/ROS/pages/30146563/LTE%205G),
[USSD T2](https://selfcare.t2.ru/help/article/ussd-commands).
